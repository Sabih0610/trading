## Implementation decisions

Version profiles by content digest and exact provider/server/environment/build/instrument scope. Distinguish UNVERIFIED, PROVISIONAL, VERIFIED, EXPIRED and INVALID. VERIFIED requires provider-authoritative evidence plus repeated independent UTC validation; a profile state string alone is insufficient. Use nonoverlapping effective UTC periods or a verified IANA zone; resolve candidates by round-trip, rejecting gaps/ambiguous folds. Keep raw representation, normalized time and profile digest together. Never retroactively reprocess old files silently.

Preserve existing finite collector, storage integrity, default-deny native tools, host UTC checks, source freshness, instrument/risk and historical holdout boundaries. Add provider identity/provenance to those components; do not build another pipeline. One unavailable instrument must not prevent another from being independently tested.
