## Existing components and necessary adaptations

- Reuse `size_candidate` for intention assessment and fill-time sizing; add an explicit assessment-only
  argument because an already-observed quote necessarily precedes a newly frozen decision. Fill calls
  retain the existing subsequent-quote requirement. Preserve actual decision time in the journal.
- Reuse ContractSpec, CurrencyConversion, BrokerContract/QuoteBook side clocks, effective_risk_limits,
  AccountCircuitBreaker/SafetyState and DecisionLedger. Extract the existing OS lock into core with
  the MT5 compatibility entry point retained; offline consumers need no broker adapter initialization.
- Share funded_flow with the legacy LocalPaperSimulator for principal and single fee debits/credits.
  The new persistent reducer orchestrates lifecycle/recovery; it does not set new risk limits.
- Use the same FeatureEngine, ShadowRuntime and EMA/channel implementations. Owned fixture processing
  delay is fixed at one simulated microsecond so frozen records are repeatable. Genuine processing
  timing remains measured. Previously committed evidence is never rewritten.

## Fixed conservative owned policy

A BUY candidate can create a funded long intention after eligibility/risk checks; it fills only on
fresh sides sourced and received strictly after the intention. Use ASK plus adverse ticks for entry,
BID minus adverse ticks for liquidation and explicit fees on both legs. Recheck cash/grid/risk at
fill; do not resize the original all-or-none quantity. Reject price drift beyond the explicit cap or
reserved funds. One pending entry reserves capital; another signal cannot release its reservation.
SELL closes owned inventory only; WAIT has no entry. Standing protection is created with the entry
and can trigger on a subsequent quote for stop, target, loss halt or end-of-day management. Target
triggers do not receive favorable gap improvement; stops use actual owned gap quotes, not a guaranteed
stop price. An explicit missed-fill event leaves the intention pending until expiry/cancellation.

Liquidation equity includes exit slippage/fees. Missing/stale sides make equity/unrealized P&L
unavailable while preserving known cash, inventory and shutdown latches. New entries fail closed.
Daily rollover follows the shared circuit; peak halts survive it. No manual account reset command.
End-of-day exits require a subsequent admissible quote; missing markets cannot manufacture flatness.

## Persistence and testing decision

One OS writer, bounded events/files/free space, FULL-sync SQLite transaction for input deduplication,
all account/order/fill effects, append-only DecisionLedger rows and checkpoint hash chain. A failed
writer is poisoned. Restart replays committed inputs and compares independently reconstructed cash,
risk, transitions, state and ledger hashes. Recovery itself has stable append-only evidence.
Snapshot export follows commit; its failure cannot roll back or duplicate a locally committed fill.
Read-only UI validates snapshot/manifest/checkpoint/ledger and independently sums fill cash flows.

Golden examples use literal cash/fee/equity arithmetic and property tests. Cost-level tests vary
only explicit costs, never strategy parameters. Fault injection covers intention, fill, exit/risk,
journal/checkpoint and reconciliation. Separate processes verify locks and replay. No true depth,
queue, market impact, stochastic latency, partial-fill or sustained broker reliability is established.
