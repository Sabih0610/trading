# P10 — Streamlit dashboard

Follow `prompts/_PROTOCOL.md`.

## Goal
A local dashboard that shows everything the system did and why, reading only from Parquet/SQLite.

## Research first
Streamlit best practices for performance (caching, fragments), multipage apps, and plotting candle
charts with annotations (Plotly). Read-only DB access patterns.

## Pages
1. Overview — equity, P&L, drawdown, win rate, expectancy, profit factor, vs baselines.
2. Trades — table + per-trade chart (Asian range, sweep, MSS, FVG, entry/stop/target, exits).
3. Decisions — every candidate setup: taken/skipped/vetoed, reasons, ML P(win), GPR band, arena votes.
4. Shadow tracking — what vetoed/skipped setups would have done; value of each filter and of human interventions.
5. Arena — model leaderboard, calibration curves, hypothesis board, disagreements, cost per model vs budget.
6. Models — versions, feature importance/SHAP, drift alerts.
7. Risk & health — limits used today, exposure, data-feed lag, API errors, cache hit rate.
8. Data — coverage and data-quality reports per dataset.
9. Controls — pause/resume flag, approve flagged trades (writes an intervention row; cannot change risk limits).

## Scenarios to self-test
Empty database · very large ledger (pagination) · missing optional tables · timezone display (UTC + Asia/Karachi).

## Acceptance
`scripts/run-dashboard.ps1` starts it; works on sample data generated by a fixture script; report written.
