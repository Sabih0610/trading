# P11h — Spot venue-status entry veto

Track H implements the approved status-only control in a separate credential-free
worktree from main. No live paper trading, external orders or historical status
fabrication is authorized. Current status can only veto an existing entry; all
deterministic risk limits and exit paths remain unchanged.

## Implementation

`tb.ingest.venue_status` projects only the four approved symbols' status strings.
The private append-only SQLite transition journal records old/new/raw status and
local receipt `known_at`; duplicate polls refresh the four-row operational state
without adding history. Poll reservation and backoff deadlines persist across
restart. Unknown, nontrading, future-only or >10-minute-old facts veto entries.

`tb.risk.venue.evaluate_entry_with_venue` rejects before the unchanged RiskManager;
TRADING delegates without changing any request, quantity or policy. No changes to
`risk/manager.py`, which is owned by Track J1. Shared paper sizing and both
proposal/fill paths accept optional immutable facts; owned Paper Lab only accepts
fixture-tagged facts. All exits remain outside this hook. BacktestEngine and
labels are unchanged; historical contract replay refuses an enabled current book.

`dashboard/venue_status.py` reads private operational JSON and recomputes staleness.
The only shared Data Health dispatcher edit is an isolated import/call, coordinated
with Track I's separate helper. No other track-owned runtime file is modified.
