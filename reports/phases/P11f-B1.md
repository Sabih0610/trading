## Permission tightening and test boundary

The asset schema previously required every tradable asset to have a nonempty
strategy allowlist. That made the approved deny-all state unloadable, including
unrelated XAUT policy. Remove only that two-line minimum requirement. The unchanged
require_strategy_allowed membership guard refuses every strategy against an empty
list, and each retired constructor still uses that real guard. Spot instrument
type, Binance Spot venue, positive pessimistic costs, data-only restrictions,
asset approval and risk checks remain enforced. No fake/sentinel strategy or runtime
bypass is introduced. This represents a stricter permission policy.

Historical mechanics tests explicitly request a validated fixture registry. Only
the three prior C/D/E allowlists differ; the fixture calls the real asset/role/
Shariah guard against it. It is not autouse and never affects the separate current-
policy regression module. All 128 prior assertions and function bodies/arguments
remain unchanged. Track H's peer source check found no concrete issue; that is not
formal Claude approval. No existing xfail or behavioral assertion was weakened.

Current-policy tests refuse all nine strategy-symbol combinations and construction
of all 162 unchanged frozen catalogue cells. They preserve XAUT C and prove registries with empty strategy allowlists still
load while malformed spot type, venue, costs and data-only
strategy permissions remain refused. Existing risk/instrument-safety tests are
unchanged. The first focused run exposed the incompatible nonempty invariant;
root authorized the exact representation change and the corrected tests passed.
