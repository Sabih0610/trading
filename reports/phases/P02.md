# P02 phase report — Historical market data

P02 delivers keyless, resumable public-history ingestion with a fail-closed immutable Bronze boundary. Binance spot and Dukascopy were validated on a real seven-day sample; live FRED remains intentionally gated by current terms, and the full transfer is waiting for adequate disk capacity.

## Summary

The downloader supports:

- Official checksummed Binance spot daily/monthly 1m klines and aggregate trades for BTCUSDT, ETHUSDT, SOLUSDT, and XAUTUSDT, with public REST klines for the current-day archive lag.
- Dukascopy M1 BID/ASK BI5 decoding for XAUUSD, seven FX references, and WTI; recent hourly XAUUSD ticks are limited to the trailing 365 days.
- A fixture-backed, allowlisted FRED CSV parser whose live path fails closed under decision D-0011.
- Exponential retry with jitter and `Retry-After`, atomic writes, streaming archive conversion, checksum validation, source-wide Dukascopy throttling, resume, disk preflight, JSONL outcomes, and a reusable validator.

The 2026-10-12 through 2026-10-18 sample contains 112 Parquet files, 12,671,061 rows, and 193,559,795 bytes. Every file passed manifest, checksum, row-count, time-order, and exact-duplicate validation. The sample covers Binance and Dukascopy M1; the XAUUSD tick path was subsequently verified with offline binary/integration fixtures, while a repeated live probe encountered the provider's temporary HTTP 429 throttle.

The full 2020-10-01 through 2026-10-21 estimate is 778.56 GB. Only 117.97 GB was free, so the job was correctly not started; it remains blocked on a larger destination rather than risking a predictable partial transfer.

## Decisions

- D-0009: use checksummed Binance monthly/daily spot archives plus public REST only for archive lag.
- D-0010: decode the keyless Dukascopy BI5 feed in Python and treat it as best-effort.
- D-0011: fail closed on live FRED use pending an owner/legal terms decision.
- D-0012: do not start the full transfer until a destination has at least 779 GB free.

See `docs/research/P02-research.md` and `docs/adr/0002-immutable-bronze-ingestion-boundary.md`.

## Known limitations

- The current disk cannot hold the conservative full-history estimate; D-0012 is open.
- The keyless Dukascopy feed is legacy/best-effort and temporarily returned HTTP 429 after the completed sample. Reruns must retain the global rate gate and use resume.
- Live FRED use and a FRED sample are prohibited until D-0011 is resolved. Fixtures prove the parser only.
- Binance has no XAUTUSDT history before its 2026-03-26 listing; these periods are explicitly logged as `not_listed`.
- Bronze acquisition includes locked final-period rows but performs no feature calculation, tuning, backtest, or evaluation on them.

## How to run

Sample:

```powershell
Set-Location -LiteralPath "E:\trading bot"
pwsh -NoProfile -File .\scripts\download-history.ps1 -Sources binance,dukascopy -From 2026-10-12 -To 2026-10-18 -Resume -Sample
```

Validate:

```powershell
uv run python -m tb.ingest.history.validation .\data\bronze
```

Full run on a sufficiently large volume:

```powershell
pwsh -NoProfile -File .\scripts\download-history.ps1 -Sources binance,dukascopy -From 2020-10-01 -To 2026-10-21 -Resume -BronzeRoot "F:\trading-data\bronze"
```

See `docs/how-to/historical-data.md` for recovery and troubleshooting.
