## 4. Clock-profile architecture

`ClockProfile` is frozen/extra-forbid and carries exact provider/broker/server/environment/instrument/build scope, semantics, timezone or explicit effective UTC periods, issued/verified/expiry dates, historical applicability, evidence references/content hashes, reviewer, repeated-validation evidence, supported kinds and refresh conditions. States: **UNVERIFIED, PROVISIONAL, VERIFIED, EXPIRED, INVALID**. MetaQuotes-Demo is configured **UNVERIFIED**, with no installed offset or DST rule.

Only VERIFIED converts. Minimum proof: scoped provider-authoritative HTTPS specification/confirmation, reviewer, at least three validation samples over ten seconds, two distinct UTC references, residual at most two seconds and live verification/expiry dates. These fields require honest review; code cannot independently authenticate a human-entered specification. No automatic profile learning/promotion occurs. Fixture validation is explicitly labeled and cannot enable genuine adapters.

Conversion uses verified UTC-effective periods or IANA round trips, rejecting overlapping rules, uncovered dates, nonexistent spring times, ambiguous autumn folds, mismatched source scope, expired rules and unexpected quote clock jumps. Historical applicability is separate from present profile freshness. `ClockStamp` preserves raw representation/time plus normalized time, rule, profile ID/digest and public identity. Profile changes never edit old files; raw-clock-based dedup prevents a changed rule from making the same original fact newly observed.

New genuine MT5 reads refuse a missing/unverified/fixture-only profile. Existing native safety, demo/path/account, independent host UTC and source freshness checks remain. Admission now masks instruments independently; a passing instrument can proceed while its sibling is unavailable. Common security/identity/host-clock failure still stops both.
