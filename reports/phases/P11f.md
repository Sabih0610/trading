## Implementation and review artifacts

D (VolatilityBreakoutStrategy) calculates a prior-only normalized ATR compression
threshold, prior range breakout and strict source-volume confirmation. E
(TsMomentumStrategy) combines the shared completed EMA20/50 features with positive
N-bar return and close-only trend-loss proposals. Every entry has a positive stop
below its planned close and a 2R target. Missing confirmation means WAIT; a gap
clears lookback without clearing daily proposal caps. Both plugins admit only the
three registered crypto symbols and their declared timeframe pairs.

StrategyBar adds optional Decimal volume, preserving existing C behavior. Shared
replay remains unchanged; a Stage 3 in-memory wrapper checks every timestamp before
consuming any bar and has no final-test option. Its pure catalogue/factory has
162 C/D/E cells and performs no data acquisition, genuine registry load or evaluation.
The only asset config changes are the three D/E allowlist additions.

[Pre-registration](../stage3/P11f-preregistration.md) freezes exact entry/exit rules,
9 configurations and 2 timeframes per candidate, 3 symbols, training ties, protocol,
per-side cost floors, ambiguities, comparisons, R/DSR/weekly bootstrap and failure
semantics. The complete owner Part B protocol/pass bar is copied word for word.
The file's exact-byte SHA-256 is recorded in the [journal](../../docs/journal/P11f-journal.md).

[Research](../../docs/research/P11f-research.md), [ADR 0022](../../docs/adr/0022-preregistered-crypto-deciding-test.md)
and [runbook](../../docs/how-to/stage3-crypto.md) explain the decisions. Source inspection
found parent context absent from existing Gold, spread half-width semantics, default
