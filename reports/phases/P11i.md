## Implementation

| Component | Change |
|---|---|
| Registry | Closed TreasuryDatasetPlan and rights-only UST_PAR_YIELD symbol; reuse existing owner/reviewer, documentary hash, revocation, original lifetime, safe paths and artifact inventory checks |
| Bronze | Original bounded CSV bytes, immutable SHA-addressed paths, per-source manifests, polite bounded retries and verified resume |
| Silver | One original publication row; all tenors in fixed Decimal percentages; missing values remain null; no calendar rows, holiday fill or interpolation |
| Gold | 2y and 10y levels; 10y minus 2y slope; changes between adjacent publication days in percentage points; no new parameter search |
| Availability | known_at = publication date 23:59:59 America/New_York, converted to UTC; only strictly later bar opens can use it |
| Shared features | FeatureEngine(enable_treasury_yields=True, treasury_context=admitted_context); default flag off adds no keys and preserves existing outputs/hashes |
| Data Health | Dedicated helper reads rights/manifest/quality metadata only; no CSV/Parquet, rate display, build action or policy mutation |
| Operations | Explicit no-key CLI; committed runtime required; single-writer lease; original rights/lifetime before source or derived reads |

A 2024-12-31 publication may have a 2025 UTC known_at timestamp because of New
York's offset. It is unavailable to every pre-2025 bar, and the enabled context
refuses 2025+ bar timestamps. This preserves the actual conservative clock rather
than moving late evidence earlier. One-day changes mean adjacent published
business-day observations, not forward-filled calendar values. The common
availability implementation is a strict backward-as-of binary search.

No asset/risk configuration changed. UST_PAR_YIELD is not an AssetRegistry or
execution instrument; its attempted tradable lookup is refused. Default native
feature hashes stay unchanged. There are no new dependencies, keys, trading calls,
backtests, model training, paper trading, Testnet, orders or sealed-forward access.
The Data Health dispatcher has one minimal helper call and clarifies that its old
historical-price collection message does not describe the separate Treasury view;
this is the only small overlap with Track H's separate status helper.

## Limitations and next step

The assigned historical availability clock is deliberately conservative. The
unversioned historical CSV may contain provider revisions; this is not a verified
point-in-time vintage archive or a claim of exact original release/revision time.
Calendar gaps are reported as absent publications, including holidays; no value is
manufactured to fill them. Nothing here establishes a predictive edge or authorizes
an ML/AI phase or an order. Keep the feature flag off unless a separately authorized
caller supplies the admitted context. Future scope or rights changes require review.
