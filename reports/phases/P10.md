## Delivered scope and reuse

The Streamlit 1.66.1 application provides five views: Overview, Markets & Strategies, Trades &
Decisions, Risk & System Health, and AI & Model Research. It reads isolated account exports and
never combines currencies or accounts. Empty workspace metrics remain unavailable; a separately
selected synthetic collection demonstrates the UI. Historical real, shadow, local paper and future
demo evidence have distinct source modes and are never inferred from a mock label.

- Overview: stored equity/capital, realized/unrealized P&L, net return, closed-trade count, win rate,
  profit factor and full-export marked drawdown, with unavailable/undefined values preserved.
- Markets: all six requested instruments, explicit research/simulation/demo/live eligibility,
  independent-approval absence, allowed strategies, insufficient research coverage, source and
  timestamps, plus stored price charts and separately timed signal/fill/exit markers.
- Decisions: accepted/rejected/vetoed/skipped records, intended and filled sizes, entry/stop/target,
  fill/exit, fees/P&L, reasons and decision/outcome IDs. Bound market/strategy/date/status filters
  and rowid-based pagination affect only the current view.
- Risk/health: actual loaded risk configuration and asset overrides, complete journal status
  counts, typed archived latch observations, data age and explicitly unavailable current health.
- AI/research: actual zero empirical counters from existing reports, restricted provider enablement
  and budget status, software/prompt/feature version IDs and the stored offline mock arena summary.
  Model calibration, trading accuracy, runtime availability and actual model value remain unproven.

P09.5 `DashboardSnapshot`, `PolicyBundle`, effective limits and `SafetyState` are reused. The fixture
CLI reuses causal FeatureEngine via `fixture_market`, existing Spot BacktestEngine, P09.5 local
contract replay, ArenaAnswer veto semantics, AccountCircuitBreaker, DecisionLedger and checksum
helpers. Risk/backtest/simulation/ML/provider source is unchanged. Only presentation metrics and
read adapters are new. Streamlit is the sole new direct dependency, exactly pinned in uv.lock.

## Read and evidence boundary

SQLite uses `mode=ro`, `query_only=ON`, normal WAL locking and short-lived connections; it never
constructs the writer, initializes schema, migrates or checkpoints. Tests keep a writer active and
prove committed WAL changes are visible while CREATE/INSERT attempts fail. Native SQLite may
maintain coordination sidecars; journal rows/schema remain unchanged.

Pages contain at most 200 decisions (UI 50). Outcome metrics stream batches of 500 independently
of pages. Parquet reads project known columns and cap charts at 2,000 observations; marked
drawdown is a full-file lazy reduction. Cached results expire in 15-30 seconds with DB/WAL or
Parquet/manifest stamps. Live DB handles are not cached.

Only explicitly indexed report exports are opened. Real reserved-period manifests are refused
before scan; an additional lazy timestamp predicate prevents incorrectly dated exports from
feeding reserved rows into charts or drawdown. Coverage contradictions invalidate the result.
No final-test flag or raw market-data volume scan exists in the UI.

Snapshots and source modes/currencies are validated. Raw payload/config/prompt dumps are excluded;
known fields are projected and credential-shaped text is masked. The application never loads
Settings or `.env`. Provider configuration enablement is not represented as a successful connection.

## Windows run instructions

From the repository root, with uv available:

```powershell
uv sync --locked
.\scripts\run-dashboard.ps1
```

Open http://127.0.0.1:8501 and choose **Synthetic demo** for the existing local examples. A running
instance is already on this loopback port. The script finds the local work/tooling uv bootstrap if
needed. On a fresh checkout generate fixtures once with:

```powershell
uv run --locked python -m tb.dashboard.fixtures
```

The generator refuses an existing output folder. Existing records are reused; another demo needs
a fresh output root and matching `-ReportRoot`. See the complete
[operator guide](../../docs/how-to/dashboard.md) for spaced-path examples, alternate ports, schemas
and troubleshooting. Ctrl+C in the server terminal stops the process.

## Remaining limitations

No real account, eligible historical dataset, feed, current risk latch, calibration evidence or
market-trained model is attached. Missing states intentionally remain unavailable. There is no
continuous paper loop, P11 reader, notification process or broker gateway.

Manifest checksums are declared provenance, not rehashed on every UI refresh; the export pipeline
must verify large-file integrity. Legacy outcome linkage can be slower without a producer-created
index; the UI cannot create one. The pagination test covers 1,205 decisions, not a million-row
performance benchmark. Live receipt-time health and future forward-paper chart authorization need
their own reviewed P11 contract; the current reader conservatively refuses real 2025+ chart data.
Missing legacy outcome fields invalidate affected metrics rather than being reconstructed.

No failing tests or observed browser render errors remain. Independent P10/P09.5 reviews are queued;
previous deferred reviews are not approvals. None of the demo results proves profitability or
independent instrument-specific Shariah/legal eligibility.

## Recommended P11a plan and future execution choice

Under a new owner instruction, implement only `ReadOnlyMarketFeed` on Windows behind optional,
mockable MT5 availability. Verify terminal/account identity without acquiring order capability;
map broker symbols to canonical XAUUSD/EURUSD; capture actual contract, tick/pip/lot/currency,
session and receipt-clock facts. Stream immutable Bronze data with manifests, then the existing
Silver/features path. Publish explicit shadow/reference observations and current health records
for the dashboard without treating historical holdouts as forward evidence.

Test missing terminal/no credentials, disconnection/reconnect, duplicates/gaps, UTC/DST/clock
changes, suffix mapping, stale/partial metadata, append-only resume and bounded memory. Do not
import or call order-sending methods, build an EA, enable demo/live eligibility or start a soak
without its separately scoped persistent runner work. P11a itself is not started here.

For P12, [ADR 0006](../../docs/adr/0006-python-ea-execution-boundary.md) compares Python direct,
minimal EA and hybrid across latency, reconnects, acknowledgement, duplication, protective stops,
account switching, security and synchronization. Conditional recommendation: Python owns research
and deterministic risk, and a minimal EA would be the sole future sender/protection boundary.
Uncertain outcomes require reconciliation before resend; no exactly-once claim is made.
Current Binance Spot execution policy does not authorize MT5 contract orders: any demo route
requires separate owner scope, policy alignment, eligibility and independent review first.
