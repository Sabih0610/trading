## Summary

`assets.yaml` contains four executable Binance spot symbols and nine market-context symbols that can never pass the trading gate. `risk.yaml` exposes human-editable limits, while immutable Python ceilings prevent looser values. Per-asset overrides must also be no looser than the active global configuration.

The guard layer rejects unknown/data-only/unapproved assets, every non-spot market, sales beyond owned inventory, exposure over equity, trade risk over 1%, daily loss at 3%, exhausted daily trade counts, and entries outside configured sessions. XAUT weekend entries fail while exits remain available to reduce risk.

## Known limitations

- Exchange filter values are intentionally null until a later public metadata synchronization phase. Null means unknown and must fail closed before order sizing.
- P01 enforces entry sessions but does not yet implement exchange holidays or event blackouts; P03 supplies calendars/news.
- `ruling_source` records owner-approved project policy. The software does not issue a religious ruling; a human may change status to pending/rejected.
- The guard functions are present but no execution path exists yet. Later phases must call the same guards rather than duplicating policy.
